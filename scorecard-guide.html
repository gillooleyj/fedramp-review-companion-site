How to read the package scorecard

Use the Review Companion to answer three questions: What did I receive? How far can I follow each claim? What should I inspect next? The counts describe the files you select. They do not predict certification or assign a percentage to security effectiveness.

Start with the current Certification Package Overview (CPO), Security Decision Record (SDR), Ongoing Certification Report (OCR) and the supporting artifacts you have. Select the class from the package. The practice counts come from two kinds of SDR entries: FedRAMP rules (FRRs) and Key Security Indicators (KSIs). If the folder includes historical copies, compare them deliberately or select just the current files before reporting counts.

Try it on the fictional example

  1. Choose Class C, load the fictional teaching example and open your v1.08 review sheet if you want an Excel copy. The example includes an SDR, a CPO, an incomplete OCR and a test record.
  2. Start with AFC-CSO-ACK and Items to reconcile. The provider reports partial implementation. The assessor’s pass refers to one tested external sender. Under Evidence to inspect, follow the reference to the receipt test and read the untested routes. Return to the practice and use Enter your review sheet findings. For Class C in the starter the destination is row 235. In I select the evidence category. In O identify the test and scope. Use L for the intent judgment, M for the sufficiency judgment and N for your reviewer status. A Concern requires a written basis in O. State what evidence would resolve it.
  3. Open step 3, Check the package as a whole. The SDR and CPO match the bundled schemas. The OCR lacks a reporting period. The test record is ordinary evidence JSON. The scorecard therefore shows 2 of 3 checked documents matched. Capture the reporting-period question in the package-level checks. Follow up on evidence and sheet rows that still need attention.
  4. For handoff, explain how the open issue affects your recommendation. You can retain Review in progress. Download updated review sheet (.xlsx) saves the mapped F–P cell edits. The team handoff gives the recommendation and open work, and the scorecard text gives counts and traces. Export review notes saves editable progress to reopen with the same package, workbook and class.

There is no overall grade. A row can match the schema, name the right indicator, contain all three narratives and still cite a test of the wrong population. Conversely, a demonstration to an assessor or evidence in a controlled repository can be legitimate even when it cannot be opened from the selected files. “No local match” is a follow-up, not a finding.

Follow a reference

Start with the file, practice ID and JSON pointer. A filename in a narrative is a citation. Inspect a uniquely matched file. When two selected files share the cited name, resolve which one the author intended. Select a folder when possible to preserve relative paths. Read linked JSON or embedded evidence at its pointer. A matched text file can be previewed locally up to 128 KiB. For a PDF or Office document, save a copy, open it on your device and cite the page or sheet you reviewed. Use Browse a source document in the practice review to search a selected JSON file or read the whole document. Check external URLs separately. The tool cannot discover a citation written in an unsupported notation or prove that it found every relevant file.

An evidence index can provide an intermediate step. For example, a narrative may cite EVD-TEST-01. If a selected JSON record explicitly pairs that identifier in evidenceId or evidenceID with evidenceLocation or evidenceText, the tool can show the cited ID, the index file and pointer, and the final target. Duplicate definitions and competing targets stay unresolved. This is a supported provider convention, not a required FedRAMP manifest format.

The SDR and OCR can also name their CPO using certificationPackageOverviewUri. The scorecard compares these declared targets and looks for a selected CPO with the same URL filename. A shared URL helps reconcile the documents. A filename match cannot establish the identity or version of the document at that URL; check the offering, scope and revision yourself.

For each trace, ask what was supposed to happen, what the evidence shows, which resources and period it covers, and which exceptions remain. In the review sheet, classify the evidence in I. Put its file, page or JSON pointer and the observed result in O. Record the automated method count and appropriateness separately in J and K, decide intent and information sufficiency in L and M, then select the reviewer status in N. The team records its discussion and next steps in Q–U.

Rule and version basis

  • FRC-CSO-PKG and FRC-CSO-JSN distinguish package information from machine-readable format requirements. The scorecard does not infer the full applicable package inventory from filenames.
  • SDR-CSO-FRR and SDR-CSX-KSI explain why reviewers trace the practice, its measures, verification, validation, independent work where applicable, and supporting material. Check the applicable class and path before treating an absence as a concern.
  • IVV-CSO-SEI, IVV-CSO-SEE, IVV-IAS-VIM and IVV-IAS-VEF distinguish evidence of implementation from evidence of effectiveness. Class A uses its alternative framework and overlay; separate FedRAMP package IV&V is optional. For Classes B/C, check independent work separately. Counting test descriptions cannot establish the number or adequacy of automated methods.
  • The Class B and Class C KSI rosters and the Class A overlay were checked November 4, 2026. The pinned reference edition identifies the comparison set. There is no denominator for all applicable FRRs in this tool.
  • Offline structure checks use snapshots from the official schema catalog checked November 4, 2026: CPO 0.2.0, SDR 1.1.1, OCR 0.2.1 and Common Definitions 0.4.2. An undeclared type is inferred from document fields. Confirm that the edition matches your review; a disagreement with this snapshot may be a version question.
